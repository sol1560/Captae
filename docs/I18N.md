# Captae 多语言（i18n）

Captae 的界面、提示、命令行输出支持 8 种语言。这份文档写规矩：怎么写要翻译的文字、词表在哪、怎么检查、各语言的译法和术语。
代码注释里说「见 docs/I18N.md」指这里。

## 1. 支持哪些语言、用哪一种

| 代码 | 语言 | 说明 |
|---|---|---|
| `zh-CN` | 简体中文 | 原文，没有词表 |
| `en` | English | 其他语言缺的条目退回英文 |
| `zh-TW` | 繁體中文 | 台湾用语；缺的条目退回简体原文 |
| `ja` | 日本語 | |
| `ko` | 한국어 | |
| `de` | Deutsch | |
| `es` | Español | |
| `fr` | Français | |

- 设置 › 通用 › 语言：「跟随系统」（默认，`settings.json` 里 `language` 为空）或者指定一种。跟随系统时用系统首选语言里第一个支持的，一个都不支持时用英文。
  中文带 `Hant`、`TW`、`HK`、`MO` 的算繁体，其余算简体。
- 桌面端、命令行、MCP、插件宿主读同一份 `settings.json`，用同一种语言。环境变量 `CAPTAE_LANG=en` 优先于设置（测试用）。
- 浏览器插件跟 Captae 实际用的语言（宿主 `hello` 回复的 `lang`）：插件里显示的错误说法、任务记录是 Captae 生成的，同一种语言才不混。
  电脑上没有 Captae、从来没连上过时用浏览器的界面语言。插件在商店和 `chrome://extensions` 里的名字、简介按浏览器语言（`extension/_locales/`）。
- **只能有一种语言的地方用英文**（2026-11-24 用户定的）：
  - 安装包窗口（dmg 背景上的字、「Applications」快捷方式的名字）
  - 给 AI 看的固定说明：MCP 的 `instructions`、工具和参数的说明、错误里的 `next`（`errors.rs` 的 `next_step`）、`skills/captae/SKILL.md`
  - 打包配置里的 `shortDescription`
- **不翻译**：日志（`tracing`、`console`）、测试断言、代码注释、开发文档（docs、HANDOFF、注释里的设计说明）、演示数据（`apps/desktop/src/dev/`、`extension-popup/mock.ts`）、
  网站自己的内容（视频标题、yt-dlp 的原文报错 `raw`）。

## 2. 写法

三处界面文字（桌面端和插件面板的 React、核心库和命令行的 Rust、插件网页部件的 JS）写法一样，和 gettext 相同：
**代码里直接写中文原文，按原文查译文**。中文（简体）就是原文，不需要词表；原文改了，其他语言的旧译文自动失效、要重新翻译。

### 2.1 三处的函数

| | 普通文字 | 句子里嵌元素 | 模块顶层的常量 | 不在代码里写死的原文 |
|---|---|---|---|---|
| 界面（`apps/desktop/src`） | `t("全部暂停")` | `tx("点<b>继续</b>接着下", { b: (s) => <b>{s}</b> })` | `N_("…")`，显示时 `t(x)` | `tAny(s)` |
| Rust（`crates`、`apps/desktop/src-tauri`） | `tr!("没有这个任务")` | | `tr_key!("…")`，用时 `i18n::dynamic(x)` | `i18n::dynamic(s)` |
| 插件 JS（`extension`） | `tr('全部下载')` | | `N_('…')`，显示时 `tr(x)` | `tAny(s)` |

- 原文必须**直接写成字符串字面量**：界面用双引号 `t("…")`，Rust 用普通字符串 `tr!("…")`（不要用 `r"…"`），插件单引号双引号都行。
  `scripts/i18n.py` 从源码里按这个样子找原文；变量、模板字符串、拼起来的字符串它找不到，词表里就不会有。
- Rust 里：核心库用 `crate::tr!(…)` 或者在文件开头 `use crate::tr;`；命令行、桌面端用 `captae_core::tr!` 或 `use captae_core::tr;`。
- 插件 JS 的函数叫 `tr` 不叫 `t`：插件代码里很多局部变量叫 `t`，会把它遮住。
- 界面的 `t()` 参数类型是英文词表的键（`i18n/keys.ts`），`tsc` 会拦下英文词表里没有的原文。所以**新加一句时先在英文词表里加上**。

### 2.2 占位符、数量、说明

- 占位符写成 `{名字}`，名字只用英文字母、数字和下划线：`t("共 {n} 个", { n })`、`tr!("登录{site}", site = name)`。
  Rust 的模板里不能写 `{:.1}` 这类格式，先格式化好再传：`tr!("从 {size} MB 处接着下", size = i18n::decimal(x, 1))`。原文里不要有其他花括号。
- **数量叫 `n`**。英文、德文、西班牙文、法文的词表里，带 `{n}` 的句子单复数不同时写成 `{"one": "{n} video", "other": "{n} videos"}`，按 `n` 选
  （法文 0 和 1 都算 one）。中文、日文、韩文只写一个字符串。
- **同一句中文在不同地方要译成不同的话**（「下载」是按钮还是页面名字），原文后面加「§说明」：`t("下载§侧栏的页面名")`。中文显示时去掉「§」和后面的部分。
  说明写清楚用在哪，翻译时看得到。
- **自动空格**：中文、日文里，占位符紧挨着汉字或假名、填进去的值以字母或数字开头 / 结尾时，自动空一格：
  `"登录{site}"` 填 YouTube 是「登录 YouTube」，填哔哩哔哩是「登录哔哩哔哩」。所以**中文原文里占位符两边不要自己加空格**（加了也不会多出一格，但没必要）。
  原文里写死的中英文之间照旧手动空一格（「用 Captae 下载」）。
- 句子里嵌元素（加粗、链接、图标）用 `tx`：标签写成 `<b>…</b>`、`<link>…</link>`（名字自己起），图标这类整块的东西用占位符 `{icon}`。
  标签里可以有占位符，标签不能套标签。

### 2.3 一句话一个条目

- **不要把翻译过的片段拼成句子**：`t("已下载") + " " + n + t("个")` 在别的语言里语序不对。整句写成一个条目，变化的部分用占位符。
- 也不要把一句话拆成两个条目再拼（「这个视频要登录」+ 站点名 +「才能看」）。
- 例外：完全独立的两句话可以分开（前一句说原因、后一句说怎么办）；列表用 `joinList` / `i18n::join`（中文、日文「、」，其他语言「, 」）。

### 2.4 存下来的、传来传去的不翻译

- **协议值不翻译**：`AddRequest.format` 的「保持原格式」、`quality` 的「最高可用」，界面和后端都按这几个中文值判断，它们不显示。
- **存进数据的名字存中文原文，显示时翻译**：素材的来源「本地」、错误里的站点名（`fail.site`，「哔哩哔哩」「芒果TV」）、登录过的网站名、
  MCP 客户端没报名字时的「AI 助手」、AI 工具的名字（`agent.rs` 的 `label`）。界面用 `tAny(name)` 显示，这些原文在 `i18n/sites.ts` 等处用 `N_` 标出来。
  后端加了新的中文站点名（`errors.rs` 的 `site_name`、`login.rs` 的 `SITES`）时，`sites.ts` 也要加。
- **预设的步骤存中文原文**（`presets.rs` 按中文解析「转为 MP4」「只留前 30 秒」，旧版也要能读）。界面显示时翻译：完整的步骤按原文查，
  带参数的按样子换（「下载 1080p」→ `t("下载 {quality}")`），见 `pages/agent/model.ts` 的 `stepLabel`。默认预设的名字在生成时翻译（还没保存过时每次按当前语言生成）。
- **后端生成、界面直接显示的文字**（任务记录、错误说法、通知、任务标题、`fmt`、`dur`、「影片 › Captae」）在后端生成时就按当时的语言写，
  换语言以后已经生成的不会变，这没关系。
- **不要拿给人看的文字做判断**：它跟着语言变。要判断时用固定的字段：错误码 `fail.code`、细分 `fail.reason`（`image_post`、`radio`）、
  短说法 `fail.brief`（去掉「可以用浏览器插件在网页里下」）、占位标题 `job.untitled`、读取开始时间 `job.probeAt`、固定代码 `NOT_RECORDING`（`errors::coded`）。
  照顾旧版数据的文字判断可以留着当退路，但不能是唯一的判断。

### 2.5 日期、时间、数字

- 界面：日期、时间用 `Intl.DateTimeFormat(lang(), …)`，时间一律 24 小时制（`hourCycle: "h23"`）；带小数的数用 `decimal(x, 位数)`（德文、法文、西班牙文用逗号）。
  **简体中文的输出要和原来一字不差**（「9月3日 10:02」「11 月 22 日」），需要时中文单独走原来的写法。
- Rust：小数用 `i18n::decimal`，时间写 `HH:MM`，相对时间（「刚刚」「3 天前」）用 `tr!`。
- 文件大小的单位（MB、GB）、分辨率（1080p）、格式名（MP4）各语言一样，不翻译。

### 2.6 界面上要注意的

- 模块顶层的常量（选项表、标签名表）**不能在加载时就调 `t()`**：那时词表还没加载，换语言也不会跟着变。用 `N_` 标出来，渲染时再 `t(x)`。
- 换语言时整个窗口按新语言重新挂一次（`main.tsx` 的 `Root`，`key={lang}`），所以组件里直接调 `t()` 就行，不用订阅语言。
  弹窗开着与否、当前页面、任务这些都在组件外面，重挂不会丢。
- 插件工具栏面板只加载 `common` 和 `popup` 两个分册：面板用到的共用代码（`lib/format.ts`、`parts/`）的文字要放在 `common` 分册。
- 译文通常比中文长（德文、法文能长一倍）：按钮、分段控件、表格列、窄窗口要留余量，不能写死只够中文的宽度。改完用演示构建看 `&lang=de`。
- 名字参数叫 `t` 的局部变量会把 `t()` 遮住（`tsc` 会报「不能调用」），改个名字。

## 3. 词表

| | 位置 | 分册 |
|---|---|---|
| 界面 | `apps/desktop/src/i18n/locales/<语言>/<分册>.json` | `common`（窗口骨架、侧栏、登录工具条、`lib/`、`parts/`）、`downloads`、`library`、`agent`（AI 助手页）、`extension`（浏览器插件页）、`settings`、`onboarding`（上手引导）、`popup`（插件工具栏面板） |
| Rust | `crates/captae-core/locales/<语言>/<分册>.json`，编译时放进程序 | `download`（下载流程、错误、下载引擎）、`core`（核心库其余部分）、`app`（桌面端外壳、命令行、菜单） |
| 插件 JS | `extension/lib/i18n/<语言>.json` | 一个文件 |
| 插件的名字和简介 | `extension/_locales/<语言>/messages.json`（Chrome 的写法，目录名 `zh_CN`、`zh_TW`） | |

- 格式：`{"原文": "译文"}`，带数量的 `{"原文": {"one": "…", "other": "…"}}`。键是完整的原文（含「§说明」）。
- 简体中文没有词表。繁体中文缺的条目显示简体原文；其他语言缺的显示英文，英文也缺就显示原文。
- 同一句原文在同一种语言的几个分册里都有时，译文要一样（运行时分册合在一起查）。
- 一个分册里条目的顺序跟英文词表一样（`scripts/i18n.py import` 写回时自动排）。

## 4. 检查、导出、导入

```
python3 scripts/i18n.py check            # 英文必须齐；其他语言缺的只报数量（运行时退回英文）
python3 scripts/i18n.py check --strict   # 所有语言都要齐，发版前用
python3 scripts/i18n.py check --area ui --lang ja -v   # 只看一处、一种语言，列出缺的和没用到的
python3 scripts/i18n.py export ja        # 导出日文缺的条目到 work/i18n/todo/ja.jsonl，每行 {id, area, part, zh, ctx, en, ph, where}
python3 scripts/i18n.py import ja FILE   # 写回译文，FILE 每行 {"id": 12, "t": "译文"}；占位符、标签对不上的不写，列出来
python3 scripts/i18n.py tidy             # 整理词表：几个分册都有的挪到共用分册，其他语言放回和英文同一个分册，源码里不用了的删掉
python3 scripts/i18n.py quotes           # 句子里「」引用的按钮名、页面名，译文要和那个名字自己的译文一样；列出对不上的
```

`check` 还会核对：占位符和标签跟原文一样、复数写法对、没有空译文、同一句在几个分册里译得一样。

新加文字的流程：代码里写中文原文 → 英文词表加上 → `check` 通过 → 其他语言 `export`、翻译、`import`（可以攒一批再翻）→ `tidy`、`quotes`。
原文改了的，旧的那句会变成「没用到」，`tidy` 删掉；新的那句在每种语言里都要重新翻。
改了界面文字以后用演示构建带 `&lang=de`、`&lang=fr` 看一遍（这两种最长），按钮、下拉框、侧栏标题行有没有被截断或挤在一起。

## 5. 字体

`theme.css`（界面）和 `extension/lib/ui.css`（插件网页部件）按 `lang` 换中日韩的字体：同一个汉字简体、繁体、日文的字形不一样。
界面在 `<html lang>` 上（`setLang` 设），插件网页部件在 `<captae-ui lang>` 上（不跟网页自己的 `lang`）。Geist 只有拉丁字母，
带重音的拉丁字母（é ü ñ ç ß œ）在它的范围里（U+0000-00FF、U+0152-0153），其余的字落到后面的系统字体。

## 6. 测试

- 演示构建：`npm run build:mock` 后带 `?mock&lang=en` 打开就是英文（不带 `lang` 时演示后端当系统语言是中文）。插件面板的演示构建也认 `&lang=`。
  演示数据（任务标题、记录、报错）照旧是中文，它代表后端发来的数据。
- `work/i18n/textdump.py`（维护者本机）导出各页面、各状态的文字，`work/i18n/textdiff.py` 和改之前的比：中文界面除了新加的「通用 › 语言」一行，应该一字不差。
- Rust：核心库的单元测试不管电脑是什么语言都按中文（`i18n::system` 在测试里返回中文），断言按中文写；要测别的语言用 `i18n::with_lang(Lang::En, || …)`（只对当前线程）。
  端到端测试在设置里写了 `language: zh-CN`。
- 命令行：`CAPTAE_LANG=en captae probe <链接>` 看英文的说法。

## 7. 译文风格

整体：和中文原文一样平实、简短、友好，说清楚发生了什么、接下来怎么办。不用感叹号，不夸张，不加原文没有的意思；原文没说的不要补。
界面上的按钮和标题要短。原文里用「」引用的按钮名、页面名，译文里要和那个按钮、页面实际的译名一字不差。

| 语言 | 称呼 | 大小写、标点 | 引用界面上的名字 |
|---|---|---|---|
| English | you | 按钮、标题、菜单项、标签都用句首大写（sentence case：「Stop and save」）；macOS 菜单栏的标准项照 Apple 的写法（Title Case）。可以用缩写（can't、don't）。美式拼写。省略号用「…」一个字符 | “Stop and save”（弯引号） |
| 繁體中文 | 你 | 台湾用语和 macOS 繁体中文的叫法（影片、檔案、資料夾、設定、登入、網路、預設、外掛→擴充功能）。不是简转繁：词要换。全角标点，中英文之间空一格（同原文） | 「停止並儲存」 |
| 日本語 | （省略） | 句子用です・ます；按钮、标题用名词或动词原形，短。全角标点「、。」，和英文、数字之间空一格（同原文） | 「停止して保存」 |
| 한국어 | （省略） | 说明用 -습니다/-ㅂ니다，请对方做的事用 -하세요；按钮用名词或短的动词。按韩文规范分写 | ‘중지 후 저장’ |
| Deutsch | du | 按钮、标题句首大写（名词照德文规范大写）。尽量短（德文最容易撑破按钮），能用短词就不用长复合词 | „Stoppen und speichern“ |
| Español | tú | 中性西班牙语（西班牙和拉美都看得懂），句首大写 | “Detener y guardar” |
| Français | vous | 句首大写。« » 里面、以及 : ; ? ! 前面用不换行空格（U+00A0） | « Arrêter et enregistrer » |

各语言另外要注意的：

- 한국어：占位符后面不要接随前一个字变的助词（을/를、이/가、은/는、와/과、으로/로），改用不变的（에、에서、의、도、만），或者换个说法，比如「{site} 로그인」。
- Deutsch、Español、Français：占位符填进来的词阴阳性、单复数不定，句子别依赖它（冠词、形容词、过去分词的配合）。德文名词照规范大写，复合词能拆成短的就拆。
- 日本語：句子用です・ます，按钮、菜单用名词或动词原形；英文、数字和假名、汉字之间空一格，和中文原文一样（自动空格也是这么加的）。
- 繁體中文：不是简转繁，用词换成台湾的说法（影片、檔案、資料夾、設定、登入、網路、預設、擴充功能、儲存、伺服器、軟體），标点用全角。

## 8. 术语表

### 8.1 Captae 自己的说法

各语言都照这张表译，同一种语言里前后一致；句子里用「」引用这些名字时，译文要和按钮、页面上实际的写法一字不差。
`Captae`、`MCP`、`Skill`、`yt-dlp`、`ffmpeg`、`aria2`、`M3U8`、YouTube、TikTok、X、Instagram 这类名字不翻译。
繁體中文照中文原文译（台湾用语），其他语言以英文为基准、意思以中文原文为准。
