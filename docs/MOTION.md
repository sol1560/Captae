# Captae 动效规范

Captae 界面里所有动效的规矩和数值。代码注释里的「配方 a」「配方 c5」指这份文档对应的小节。
数值的来源：Emil Kowalski《Animations on the Web》课程里的曲线和时长，加上对几款参考应用录屏的逐帧实测。
这里只写我们自己的取值和理由，课程的练习代码不放进仓库。

## 1. 全局约定

### 1.1 曲线（CSS 变量在 `apps/desktop/src/theme.css` 的 `:root`）

| 变量 | 值 | 用在 |
| --- | --- | --- |
| `--ease-out-quint` | `cubic-bezier(.23, 1, .32, 1)` | 默认：进场、退场、弹层、提示 |
| `--ease-out-quart` | `cubic-bezier(.165, .84, .44, 1)` | 浮在内容上的小面板（窄窗口的详情浮卡、窄窗口的侧栏） |
| `--ease-out-quad` | `cubic-bezier(.25, .46, .45, .94)` | 按压缩放 |
| `--ease-in-out-cubic` | `cubic-bezier(.645, .045, .355, 1)` | 已经在屏幕上的往返：描线、呼吸、抖动 |
| `--ease-height` | `cubic-bezier(.25, 1, .5, 1)` | 高度变化（展开收起） |
| `ease` | 浏览器内置 | 只用于悬停、颜色、背景、透明度这类小变化 |
| `linear` | | 只用于匀速的东西：进度条、倒计时、转圈、流光 |

不用 `ease-in`：它起步慢，用户最在意的那一下反而最迟钝。affectUI 弹窗自带的退场是 ease-in，在 theme.css 里换成了 `--ease-out-quint`。

### 1.2 时长

| 什么 | 时长 |
| --- | --- |
| 按压 | 160ms，`--ease-out-quad`，`scale(.97)`（小圆按钮 `.95`，大块卡片 `.98`） |
| 悬停颜色 | 120ms `ease`（`--t-hover`，桌面端、插件面板、注入网页的部件同一个值；参考实测进 92ms、出 100–108ms。侧栏、列表行的悬停和选中是即时的，不过渡） |
| 提示（tooltip） | 首个等 500ms，进场 160ms（affectUI 自带，从触发的那一边漂 3px）；300ms 内移到相邻的立刻出现、不做动画 |
| 菜单、右键菜单、下拉、小弹层 | 用 affectUI 自带的进场：菜单、右键菜单、小弹层 220ms（侧向子菜单 160ms），下拉列表 200ms（都在课程的 150–250ms 里）；`scale .96–.98` 起，从触发点长出来。关掉时直接消失（affectUI 没有退场；退场越短越简单越好）。菜单项、下拉选项的高亮块即时跟手（affectUI 自带 180ms 滑动，theme.css 里关掉） |
| 弹窗 | affectUI 弹窗进 260ms（从下方 8px + `.97`）、退 150ms（affectUI 的 ease-in 换成 `--ease-out-quint`），遮罩进 180ms、退 200ms；上手引导卡片进 200ms（`.98`）、退 150ms。都从中间出来（弹窗不跟触发点） |
| 小面板滑入 | 进 200ms，退 150ms |
| 高度展开 / 收起 | 270ms / 200ms |
| 箭头旋转（分节展开收起） | 200ms `--ease-in-out-cubic`（纯旋转用 ease-in-out，课 02/02；下载详情、AI 助手、插件页统一） |
| 图标互换（暂停↔继续、复制↔已复制） | 100ms |
| 状态互换 | 弹簧 `{duration: .3, bounce: 0}`（课程的文字和状态互换值；新任务进列表仍是 .4） |
| 封面、缩略图读到 | 300ms `--ease-out-quint`，opacity + 3px 模糊（素材库图多，只动透明度）；这次打开以来读到过的直接显示，不重播 |
| 提示条 | Sonner 自带：进 400ms `ease`（课 02/03 的原值），可以滑走 |

UI 动画一般不超过 300ms；超过的要说得出理由（元素大、走得远、或者第一次使用的引导）。退场比进场短。

### 1.3 弹簧

一律 `bounce: 0`，不回弹。用 Motion 的写法：`{ type: "spring", duration: 0.3 | 0.4 | 0.5, bounce: 0 }`。
只有手势带了速度（拖拽松手）才考虑一点点回弹，Captae 现在没有这种地方。

### 1.4 该不该动（按使用频率）

| 频率 | 做法 | Captae 里 |
| --- | --- | --- |
| 每天上百次、键盘触发 | 不动 | 侧栏切页、方向键选任务、菜单项和下拉选项的高亮、分段控件用方向键切换、快捷键、跟着打字变的提示 |
| 每天几十次 | 去掉或减到很轻（≤150ms，只动透明度） | 悬停、点选任务后右侧详情换内容（120ms 淡入，键盘换的直接换） |
| 偶尔 | 标准动效 | 弹窗、菜单、提示条、新任务进列表、详情浮卡 |
| 很少、第一次 | 可以多一点讲究 | 上手引导、下载完成打勾 |

进度、速度、剩余时间这些数字只用等宽数字防抖，不做滚动或弹跳。

### 1.5 减少动效（系统设置里的「减少动态效果」）

去掉位移和缩放，保留透明度和颜色，状态变化仍然看得懂：
- React 根上 `<MotionConfig reducedMotion="user">`，Motion 的位移、缩放、布局动画自动变成只淡入淡出。它管不到写成字符串的 `transform`：`Swap`、`IconSwap`、窄窗口浮卡、剪贴板卡、多选工具条、上手引导的退场都用 `useReducedMotion()` 自己换成只淡入淡出。
- CSS 动画各自写 `@media (prefers-reduced-motion: reduce)`：按压不缩放（affectUI 的按钮和分段控件只把时长改成 1ms、按下照样缩，theme.css 里一起去掉）、进度条直接跳到新值、流光去掉、呼吸点停在代表帧、描线直接显示终态。
- 倒计时圆环按秒跳：`Countdown` 直接按剩下的秒数写，和旁边的数字同一刻变（中途重新挂载也对得上，不用 `steps()`）。
- affectUI 的菜单、右键菜单、小弹层、下拉列表、提示、弹窗：它自己在减少动效时改成 1ms（提示直接不动），一下子蹦出来；theme.css 换成只淡入，时长照原来的（220 / 220 / 220 / 200 / 160 / 260ms）。弹窗关掉时 affectUI 在 JS 里马上卸掉，直接消失。
- 提示条：Sonner 在减少动效时把过渡全关了；theme.css 补回进场 200ms 透明度（位置直接到位），收走照旧直接消失。
- 展开收起（`parts/index.tsx` 的 `Collapse`）：不动高度，只 150ms 淡入淡出；展开时内容直接占好位置再淡入，收起时原地淡出、淡完才让出空间。
- 系统开了「减少透明度」时，玻璃换成不透明的底色。

### 1.6 性能

- 只动 `transform` 和 `opacity`（加上 `clip-path`、小于 5px 的 `filter: blur`）。例外：侧栏收起时的宽度（低频）、分节展开的高度（内容少）、affectUI 按钮换字时的宽度（它自带，见第 4 节），都写明了理由。
- 要稳的地方写整条 `transform` 字符串（课 04/02）：`Swap`、`IconSwap`、上手引导退场、窄窗口浮卡、剪贴板卡、多选工具条。实测 Motion 14.14：没有布局动画、没有 `onUpdate` 时，`x` / `y` / `scale` 简写其实也会交给浏览器跑；但条件多，元素在做布局投影、有 `onUpdate` / `transformTemplate`、上面已有 `transform` 都会退回主线程（引导卡片退场的 `scale` 实测就在主线程），所以不依赖它。
- 字符串要从具体值起步：从 `none` 缩到 `scale(.5)`，Motion 会当成从 `scale(0)` 起（实测第一帧 .098），所以图标、卡片停着时写 `scale(1)`；位移从 `none` 到 `translateY()` 没问题。动完把 `filter` 清成 `none`，不在每一行上留一个 `blur(0px)` 的滤镜层。
- 列表行要做布局让位，只能用 Motion 自己的变换（实测在主线程逐帧算），行数超过 40 关掉。
- 不给 `backdrop-filter` 做动画。不预防性加 `will-change`。
- macOS 上是 WKWebView（Safari 内核），模糊和布局动画要在真机上看。

## 2. 用 CSS 还是 Motion

默认 CSS（transition、`@starting-style`、keyframes 只用在循环和一次性的东西上）。只有 CSS 做不到的才用 Motion：真弹簧、列表增删时其余行让位、元素卸载时的退场、高度到 `auto`。
浏览器插件注入网页的部件全用 CSS（不给每个网页多加一个 React）。

## 3. 各处的做法

**a. 侧栏**：切页不动画（每天上百次）。悬停和选中即时。收起和展开：宽度 250ms `ease`；窄窗口时侧栏变成浮层，从左边滑进来 200ms `--ease-out-quart`、收起 150ms，遮罩跟着同进同出（进 200ms、退 150ms，只动透明度，`ease`）。

**b. 粘贴链接的输入框**：聚焦光圈 120ms `ease`（`--t-hover`）。识别出的链接类型直接换（跟着打字变，不动画）。正在识别超过 300ms 才出转圈，不到 300ms 的不闪。

**c. 下载列表**
- c1 新任务：进场 opacity + 从上方 8px，弹簧 0.4s；其余行同时让位（行数超过 40 时关掉布局动画）。换页签、刚打开时不播进场。
- c3 取消、移除：opacity + `scale .95`，150ms，其余行同时合拢。
- c4 往前排、往后排：布局动画（弹簧）。
- c5 进度条：`clip-path` 填充，`linear`，过渡时长等于后端推进度的间隔（yt-dlp 250ms、M3U8 400ms、aria2 1s），看起来是匀速往前；刚出现时不从 0 重播。不知道总大小时是一道流光（1.1s 移动 + 0.4s 停）。
- c6 速度、剩余时间：不动画，只用等宽数字。
- c7 暂停↔继续：图标先出后进，`scale .5` + 4px 模糊，100ms。
- 状态块（读取中 → 选清晰度 → 进度 → 完成/失败）：新的从上方 8px + 4px 模糊进来，旧的往下出，弹簧 0.3s（整条 transform 字符串，动完清掉 filter）。带进度条的几种状态（下载中、暂停、排队、处理中）之间不播互换。读取中那行「正在读取视频信息…」用 `cp-wait` 扫光（同 m）。录直播中的红点是静止的。

**d. 清晰度和倒计时**：分段控件用鼠标点时是 affectUI 自带的滑动（参考录屏里同一个控件就是滑的；滑块两边分开走，朝目标那边 270ms、另一边 400ms，`--ease-out-quint`；按住时滑块缩到 .97）；用方向键、Home、End 换时直接到位。「几秒后自动选」的圆环是 `linear`，时长等于剩下的秒数；减少动效时按秒跳，和数字同一刻变。

**e. 右侧详情**：点选任务后 120ms 透明度交叉淡化，不位移不缩放；键盘换的直接换。步骤时间线：只有在详情里看着它一步步往前走时才描线画勾（圆 250ms、勾 200ms 晚 150ms 开始，`--ease-in-out-cubic`），打开时已经完成的直接显示终态。进行中的那一步是呼吸点（opacity .45↔1，1s 往返）。分节展开收起 270ms / 200ms，箭头转 200ms `--ease-in-out-cubic`。封面这次打开以来读到过的，换任务时直接显示，不跟着卡片再淡入一遍（一个容器只做一次入场）。窄窗口的详情浮卡：从右边滑进来 200ms `--ease-out-quart`、收起 150ms。

**f. 菜单、下拉、提示、弹层**：affectUI 自带进场，都从触发点长出来（`transform-origin` 跟着方向），菜单项不错峰；关掉时直接消失。高亮块即时跟着鼠标和方向键（affectUI 自带 180ms 滑动，theme.css 关掉）。减少动效时只淡入（见 1.5）。

**g. 弹窗**：affectUI 自带进场（260ms，从下方 8px + .97）；退场 150ms，affectUI 的 ease-in 改成 ease-out（theme.css；实测 Chrome 和 WebKit 里都生效）。遮罩是中灰洗白（`--scrim`），不是压黑，不给遮罩的模糊做动画。减少动效时只淡入，关掉直接消失。登录窗口是单独的系统窗口，出现和消失交给系统。

**h. 提示条和剪贴板提示**：提示条用 Sonner 自带的动效（进 400ms `ease`，可打断、悬停暂停、可以滑走；减少动效时只淡入 200ms）。提示条放在浏览器顶层，设置这类弹窗开着时也浮在上面（看得见、点不了）。剪贴板提示卡：进 200ms、退 150ms，同一个方向，不弹跳；又复制了新链接时原地换文字（150ms 淡入），不重播进场；15 秒后自己收起，鼠标停在上面时不收。

**i. 上手引导**：第一次使用，可以多一点讲究，仍然不回弹。卡片进 200ms（`.98` 起，CSS），关掉 150ms（`.98` + 淡出，整条 transform 字符串）。翻页是 300ms 的模糊交叉淡化（位移带方向）；页码点 150ms。插画的闲置动画只在引导里，常驻界面不放无限循环。

**j. 素材库**：卡片悬停只出描边（透明度 120ms），不抬起不放大；按下 `scale(.98)`。筛选、排序、搜索不动画。缩略图第一次读到时淡入 300ms（网格里图多，只动透明度）；这次打开以来读到过的直接显示，换筛选、换素材都不重播。剪辑的胶片条：帧刚取到时从封面淡入 300ms，同一条素材淡入过就不再重播。胶片条拖动 1:1 跟手、不加缓动。

**k. AI 助手页**：连接状态点只在「连接中」时呼吸，已连接/已断开是静止的；颜色变化 120ms `ease`。新的调用记录只淡入，不位移、不错峰；用户在往上翻看时不改变滚动位置。

**l. 浏览器插件**：注入网页的按钮、菜单、进度卡片纯 CSS，只动 `transform`/`opacity`，放在 Shadow DOM 里。视频上的按钮：停留 100ms 才出现，150ms 出现、100ms 消失，从所在的角长出来。清晰度菜单进 200ms、出 150ms，用键盘打开、关掉不动画。进度卡片从屏幕下边上来 200ms `--ease-out-quart`、退 150ms，其余卡片同时合拢。悬停颜色 120ms（和桌面端同一个值）。工具栏面板不做打开动画（浏览器自己画的窗口，每天高频打开）。

**m. 状态反馈**：成功打勾见 e；失败静止不闪，用户点了重试又失败时抖一次（振幅递减、正负交替，约 300ms）；要登录、要验证静止不循环；转圈只在等待超过 300ms 时出现。有状态文字、没有进度数字的等待（读取视频信息、AI 调用进行中、看有没有字幕、读取更多）不放转圈，让文字本身扫光：affectUI `ShimmerText` 加 `cp-wait`，一次 2.7s、前 21% 匀速扫过、其余停住（参考 m5 实测 2.745s 一次、344pt/s），同样等 300ms 才出现（下载列表里「正在读取视频信息…」是这一行的状态字，一开始就在；读取一般要一秒以上），减少动效时不扫。

## 4. 有意保留的偏差

和第 1 节的通则不一样、但有理由留着的几处（2026-11-24 全应用评审时逐个量过）：

| 哪里 | 现在 | 为什么留着 |
| --- | --- | --- |
| 新任务进列表、其余行让位（下载、AI 调用记录、插件页、预设） | 弹簧 0.4s，在主线程逐帧算 | 布局让位只能用 Motion 自己的变换；整行宽、其余行要走一整行的距离（约 110px），课程允许大元素、长距离更长；超过 40 行关掉 |
| affectUI 按钮换字（如「导出片段 · 1 分 29 秒」→「正在导出」） | 宽度 480ms、`cubic-bezier(.25, 1, .5, 1)`（写在 JS 里的 WAAPI） | affectUI 自带，源码不改、theme.css 管不到；曲线很陡，实测一半 96ms、九成 229ms；只是一个按钮；减少动效时不动 |
| 分段控件用鼠标点 | 滑块落后的那一边 400ms | affectUI 自带，计划里定过保留滑动；朝目标的一边 270ms 先到，九成 132–182ms；方向键已经改成直接到位 |
| 侧栏收起、分节展开、页码点 | 动宽度、高度 | 低频、子元素少（课 07/02 同类取舍） |
| 上手引导翻页 300ms、剧照 430ms | 超过 300ms | 第一次使用，课程允许多一点讲究 |
| affectUI 菜单用键盘打开 | 也播 220ms 进场 | 一天顶多几次；affectUI 没给区分键盘和鼠标的属性；插件里自己写的菜单已经区分 |
| 素材库移到废纸篓 | 那张卡直接消失，其余卡片直接补位 | 网格可能有几百张，布局让位全在主线程；下面有「已移到废纸篓 · 撤销」提示条交代发生了什么 |

- 窗口按钮（Windows / Linux 自己画的最小化、最大化、关闭）按下不缩放，只变底色：系统自己的窗口按钮都不缩放，Windows 的按钮贴着窗口边，一缩就露出缝（2026-11-24）。

### 4.1 手机端（2026-11-25）

手机 App（`apps/ios`、`apps/android`）照这份文档的数值，换成 SwiftUI 弹簧和 Compose `spring` / `tween`；评审记录在维护者本机的 `work/mobile/motion-review.md`。和通则不一样、有理由留着的：

| 哪里 | 现在 | 为什么留着 |
| --- | --- | --- |
| Android 取消、移除下载任务 | 只淡出 150ms，没有 iOS 那样的 `scale .95` | 列表行的进出场交给 Compose `animateItem`，它只管透明度和让位，管不了缩放；为一个低频动作绕开它不值得 |
| Android 系统「移除动画」 | 所有动画直接跳到终点，连淡入淡出也没有 | Android 的这个设置就是把动画时长缩放设成 0，Compose 照它走；App 跟系统语义一致，不另外硬留淡入淡出（iOS 的「减少动态效果」仍然只淡入淡出） |
